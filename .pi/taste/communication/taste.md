# Communication
- Writes to the agent in Vietnamese; reply in Vietnamese. Confidence: 0.8
- For investigation and audit tasks, wants a thorough search but a concise single combined report with file:line references. Real testing over speculation; when unsure, test the hypothesis and report findings (HTTP status, latencies, concrete metrics) + root cause + one-liner judgment. Confidence: 0.65
- Gives terse go-aheads ("oke làm đi", "làm luôn", "tiếp tục", "đổi đi, rồi chạy luôn", "oke làm hết đi", "đã đăng nhập rồi, check lại đi", "theo đề xuất đi", "cập nhật luôn" = apply the option the agent just recommended) to finish the listed remaining/follow-up work, so the agent should just do natural follow-ups instead of stopping to ask. Confidence: 0.90
- For multi-phase feature work, asks to spawn background workers to keep progressing ("spawn workers để làm liên tục"). Prefers the agent to wait for worker completion notifications rather than polling, then verify build/tests and report back. Confidence: 0.4
- When the agent offers lettered options (e.g. "A — ...; B — ..."), the user answers with just the letter (e.g. "a"), but may also ask for several options combined ("cả a và b luôn"), or say "làm hết đi" to implement all of them. Keep such choice prompts short and lettered so a one-letter reply is enough. Confidence: 0.45
- When a proposed option has a stated risk, asks the agent to fix or mitigate that risk rather than drop the option. Is bothered by unclear or confusing trade-offs, so wants risks spelled out with concrete mitigations. Confidence: 0.35
- A question ("nếu bỏ X thì làm sao...?") is not approval to change anything. Answer the question, don't modify DB/config, and wait for an explicit yes/no. Confidence: 0.4
- Questions arbitrary choices ("tại sao phải ... combo này?"). Before changing config, check that the target fits, e.g. that a combo actually has models, and briefly explain why it was picked over the alternatives. Confidence: 0.35
- In usage stats UI, keep input (prompt) token counts in `text-primary` bold and output (completion) token counts in `text-success` bold, consistent across components (e.g. OverviewCards, RecentRequests). Confidence: 0.4
- Wants minimal, working code changes with no new dependencies. Confidence: 0.4
- After finishing an implementation, asks the agent to smoke test it in a live run ("xong rồi smoke test thử", "smoke test các trường hợp có thể xảy ra đi", "smoke test toàn bộ case đi") rather than stopping at build pass; wants multiple relevant scenarios/edge cases covered, not just one happy-path check. Confidence: 0.5
- Pastes raw runtime/proxy logs with no extra context and asks "lỗi này là sao" (what is this error). Wants a plain-Vietnamese explanation of each log line, separating root cause from downstream effects, then concrete next steps. Confidence: 0.3
- When facing an unproven hypothesis or inconclusive one-off test, prefers the agent to rank options by risk/effort (low-risk live experiment → medium investigation → large code refactor) and propose starting with the smallest, rather than jumping directly to the largest fix. Confidence: 0.65
- When a live test hits a blocker (e.g. a model provider out of credits), wants the agent to switch to a working alternative and finish the run rather than stop and report. Confidence: 0.4
- Probes for leftovers right after a "done" report ("còn X thì sao"), so before declaring setup complete, audit the related-but-unmentioned pieces yourself (e.g. every hardcoded name in config such as `models: ["team", "council"]` in src/sse/handlers/chat.js must resolve to something that exists) and report dangling references up front. Follows up with "rồi khi nào X mới được gọi tới" (when is X actually invoked) to test whether a claimed setup really works end to end; the agent should trace the real call path and admit unverified claims. Confidence: 0.5
