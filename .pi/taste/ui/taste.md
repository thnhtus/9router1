Same for non-essential app chrome: asked to hide the "new version available" update banner in the sidebar ("ẩn phần update new version ở sider đi") — acceptable fix was disabling the background version check so `updateInfo` stays null rather than conditionally rendering the card. Prefers removing clutter over polishing unused features. Confidence: 0.6
- Prefers dedicated sidebar menu items/pages for distinct features rather than embedding them into existing pages (e.g. "làm riêng ra 1 menu luôn"). Confidence: 0.5
- On large screens, page content side whitespace is too wide; prefer widening content containers (avoid overly narrow max-width like max-w-7xl) so less empty space on both sides. Example applied: DashboardLayout wrapper max-w-7xl → max-w-[120rem] with 2xl:px-12. Tends to iterate with terse requests ("nới ra nữa đi" = widen more) pushing toward near-full-width (e.g. max-w-[160rem] on a 2560px screen) across multiple pages, not just one layout file. Confidence: 0.7
- Prefers charts centered horizontally within their containing card (e.g. Activity card chart centered). Confidence: 0.5
- For adjacent cards in a dashboard grid row, prefer equal height via grid stretch with internal scrolling for long lists, over fixed pixel heights (e.g. Recent Requests matched to Provider topology height by dropping height: 480 and using absolute inset-0 scroll). Confidence: 0.5
- When polishing table/UI text styling, preserve English text content unchanged to avoid breaking i18n/RTL logic; fix layout and CSS only (e.g. add `break-all`, `whitespace-nowrap`, `tabular-nums` but don't rephrase or retranslate). Confidence: 0.7
- For dialogs/modals that show code or wide content, prefers widening the modal (e.g. `sm:max-w-[110rem]`) so content fits fully rather than scrolling; and groups the action buttons together on one side (right), styling the secondary action (e.g. Done) as `variant="outline"` so it doesn't compete with primary. Confidence: 0.6
